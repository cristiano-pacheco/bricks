## Scope and evidence

The scan covers revision `eafd28db2b2c4c53046a7d5bd31b1a494d654924`. It found 24 Go packages, 586 exported declarations or members, and 16 package READMEs. It parsed every non-test Go file under `pkg/` with Go's standard-library AST parser. ## Foundation packages

- config source in `pkg/config/config.go` supports whole-document `New[T]`, subtree `WithPath`, `Config.Get` and Fx Provide in `pkg/config/provider.go`. It requires `base.yaml`, optionally overlays the file selected by `APP_ENV`, and defaults the environment to `local`. `APP_CONFIG_DIR` defaults to `config` relative to the process working directory and also accepts absolute paths. The loader resolves recursive `env://NAME` values with `os.Getenv` before merging files. Missing variables become empty strings. It unmarshals `config` tags and reports directory, file, path and unmarshal failures. Destination `references/config/usage.md` owns these behaviors and their examples.
- logger configuration in `pkg/logger/config.go`, constructors and methods in `pkg/logger/logger.go`, and options in `pkg/logger/options.go` distinguish `New` with explicit configuration from option constructors that start with `DefaultConfig`. Defaults are info, JSON, stdout and stderr; development configuration uses debug and console. Options cover level, encoding, development, caller, stacktrace, outputs, fields and sampling. Invalid levels fall back to info. Child loggers and field helpers share the parent backend. Fatal exits and Panic panics. Direct callers own `Sync`; the lifecycle constructor registers it on stop. The module in `pkg/logger/fx.go` loads `app.logger` and binds `logger.Logger`, not `*slog.Logger`. Destination `references/logger/usage.md` must distinguish constructor errors, panic variants and shutdown failures.
- errs in `pkg/errs/errs.go` exposes structured HTTP status, code, message, detail fields, `ErrRecordNotFound` and `OriginalError`. JSON omits status and original error. `Error()` formats code and message. There is no `Unwrap`; storing `OriginalError` does not make `errors.Is` traverse it. Destination `references/errs/usage.md` must state that limitation.

## Storage and migrations

- PostgreSQL configuration in `pkg/database/config.go` requires host, database name, user and a port in range. SSLMode selects require or disable; certificate fields apply only with SSL enabled. DSN defaults timezone to UTC and includes optional application name, search path, millisecond statement/lock/idle-transaction timeouts and a seconds connect timeout. `PostgresDSN` emits a different URI representation with fewer parameters. `Clone` copies the configuration fields, including interface values; it does not clone interface-owned state. `WithDatabase` replaces the name. New in `pkg/database/database.go` uses three connection attempts, one-second exponential retry delays, a ten-second retry context, and fixed one-hour connection lifetime and ten-minute idle age. It applies positive open/idle limits only. GORM settings include prepared statements, transaction behavior, foreign-key migration constraints, logging and naming. `PreferSimpleProtol` is exported but not applied to `postgres.Config` in `connect`. The module in `pkg/database/fx.go` loads `app.database`, creates the connection eagerly and closes on Fx stop. ConnectionStats in `pkg/database/stats.go` is a data type without a public collector function. Plan `references/database/usage.md` and `recipes/postgresql-migrations.md`.
- SQLite configuration in `pkg/database/sqlite/config.go` accepts DSN or Path, not both. It normalizes connection query settings, removes their aliases, forces foreign keys on, defaults WAL journal mode, immediate locking and five-second busy timeout, and fixes the pool to one open and one idle connection. Zero pool fields receive defaults, not an unlimited pool or no idle connection. Busy timeouts must be zero or at least one millisecond. Mode, lock and pool validation have separate sentinels. GORMConfig supports overrides alongside legacy spelling aliases; runtime Logger and NamingStrategy are excluded from config decoding. Construction in `pkg/database/sqlite/database.go` opens and pings SQLite, closes failures and assigns direct close ownership to the caller. The module in `pkg/database/sqlite/fx.go` loads `app.sqlite`. Plan `references/database/sqlite/usage.md` and `recipes/sqlite-migrations.md`. Examples need CGO.
- PostgreSQL and SQLite modules both provide unnamed `*gorm.DB`. `recipes/multiple-databases.md` must demonstrate explicit named providers and consumers instead of installing both unchanged.
- Migration FileSystem in `pkg/migration/filesystem.go` wraps `fs.FS`. Runner.Up in `pkg/migration/runner.go` reads each contribution's flat root, skips directories, merges by filename with later contributions overwriting collisions, and uses the PostgreSQL migrate driver. ErrNoChange succeeds; there is no public PostgreSQL down operation. SQLite migrations in `pkg/migration/sqlite.go` have separate semantics. They parse every flat-root file, reject duplicate version/direction pairs and malformed filenames, check dirty/newer/malformed schema versions, and run pending changes in one transaction. `DownSQLite` explicitly applies all matching down migrations in descending order for development. Missing down files fail. SQLite operations retain caller ownership of the database. Plan `references/migration/usage.md`, `references/migration/postgresql.md` and `references/migration/sqlite.md`.

## Redis

Configuration in `pkg/redis/config.go`, client creation in `pkg/redis/redis.go` and Fx bindings in `pkg/redis/fx.go` support four separate topology references:

- `references/redis/standalone.md` covers `single_node`, URL parsing and DB range 0 through 15.
- `references/redis/cluster.md` covers URL or ClusterAddrs, redirects and read-only configuration.
- `references/redis/sentinel.md` covers SentinelAddrs and MasterName, sentinel credentials and replica/read-routing fields.
- `references/redis/failover.md` covers URL-derived sentinel address plus MasterName. It is not equivalent to using the SentinelAddrs configuration branch.

`references/redis/usage.md` owns shared configuration, wrapper APIs and limitations. Zero-valued durations receive defaults of five-second dial, three-second read/write, four-second pool wait, thirty-minute idle age, one-hour lifetime, five-second command timeout, and retry backoff of eight through 512 milliseconds. Other defaults include pool size ten, minimum idle two and three retries. Constructors apply defaults before validation. Config validation and dispatch do not normalize the stored Type identically; mixed-case or whitespace values need verification before examples endorse them.

TLS settings have topology-specific application. A nonempty Config.Password enables TLS even without EnableTLS. Namespace methods explicitly transform keys; raw UniversalClient operations do not apply namespaces. `Module` supplies UniversalClient while `ClientModule` supplies the wrapper. Both load `app.redis`, connect during construction, ping again on start and close on stop. The wrapper exposes config, pool stats, closed-state checks and a second-close error.

Option setters in `pkg/redis/options.go` populate ConnectTimeout, MaxRetries, RetryDelay and OnDisconnect, but current client code does not consume those values. OnConnect and OnRetry do execute. Config.CommandTimeout and UnstableMode are not applied by client construction. The spelling `DisableIndentity` is the actual public config field. Wrapper metrics in `pkg/redis/stats.go` record constructor retry pings only, not arbitrary UniversalClient commands. These are source observations; runtime examples must verify effects rather than repeat broader README promises.

## HTTP, validation and pagination

Ticket 04 adds the [validation guide](../references/validator/usage.md) and [pagination guide](../references/paginator/usage.md), with separate complete examples behind conditional pointers. [Acceptance evidence](validation-pagination.md) records source inspection, coverage, routing cases, token estimates, and the user's verification waivers. The affected branches remain planned because compilation and runtime verification did not run. Existing READMEs remain in place.

- JSON request helpers in `pkg/http/request/request.go` default to 1,048,576 bytes, permit a missing Content-Type, accept exact `application/json` after stripping parameters, reject unknown fields and map decoding failures to structured errors. Invalid decode destinations panic. The single-value check uses `Decoder.More`; later request examples must exercise trailing JSON and malformed trailing content before describing its guarantee. Parsing does not invoke a validator. Plan `references/http/request/usage.md` without mandatory server or storage loads.
- Chi Param in `pkg/http/server/chi/request/request.go` delegates to Chi URLParam. Its own package area is `references/http/server/chi/request/usage.md`, even though it has no README.
- Validator in `pkg/validator/validator.go` supports struct and scalar validation, Struct/Var aliases, required-struct mode and English translation registration. Returned validation errors remain go-playground errors. Engine and Translator permit custom rules, aliases and translations. The Fx module in `pkg/validator/fx.go` binds the Validator interface. Plan `references/validator/usage.md`.
- Paginator in `pkg/paginator/paginator.go` separates strict query parsing from normalization/capping. Blank inputs use supplied defaults without validating those defaults. Invalid explicit positive integers return page-specific sentinels. Offset/Limit return zero for invalid values; TotalPages returns zero for nonpositive count or page size. Metadata is a data struct, not an automatic response builder. OptionalTrimmedStringPtr supports optional filters. Plan `references/paginator/usage.md` and `recipes/pagination-response.md`.
- Response helpers in `pkg/http/response/response.go` distinguish enveloped JSON, raw JSON and empty 204 responses. They marshal before writing status, add supplied header values, and return marshal/write errors. The error handler in `pkg/http/response/error_handler.go` maps validation errors to 422, structured errors to their status, zero status to 500, and unknown errors to a generic 500 body. It can translate validation fields and fall back to slog for response-writing errors. The module in `pkg/http/response/fx.go` requires validator and logger interfaces. Plan `references/http/response/usage.md`; do not carry unsupported performance claims forward.
- Chi configuration in `pkg/http/server/chi/config.go` has explicit Default values, rather than automatic default merging in New. Address takes precedence over Port. Default timeouts are 15-second read/write, 60-second idle and ten-second shutdown; default ports are 8080 and 9090. Server in `pkg/http/server/chi/server.go` provides RequestID, optional request logging, Recoverer and healthz. Routes need SetupRoutes before manual Start; Fx gathers `group:"routes"` contributions and sets them up before starting. Addr exposes effective listener addresses. Startup binding errors and one-start restrictions need runtime examples. Options mutate Config and are not variadic New parameters. Plan `references/http/server/chi/usage.md` and `recipes/http-flow.md`.
- `references/http/server/chi/middleware.md` owns CORS, request/route logs and router extension. `references/http/server/chi/swagger.md` owns Swagger enablement, wildcard paths and generated docs registration. SwaggerConfig has no Dir field despite its source comment mentioning one. Chi's optional lifecycle logger is `*slog.Logger`, distinct from logger.Module's interface.

## Metrics and tracing ownership

- Use-case collectors in `pkg/metrics/usecase_metrics.go` register globally during construction. Duration is seconds with a name label; success/error counters use that label too. Duplicate registration fails. A later registration failure does not undo prior successful registrations. There is no shutdown unregister API. Plan `references/metrics/usage.md`.
- Database pool metrics in `pkg/database/pool_metrics_fx.go` and Redis pool metrics in `pkg/redis/pool_metrics_fx.go` read `app.database.metrics.enabled` and `app.redis.metrics.enabled` while building module options. When enabled they require application-owned clients and a prometheus.Registerer, register on start and unregister on stop. They do not own clients. Plan `recipes/database-pool-metrics.md` and `recipes/redis-pool-metrics.md`.
- Independent metrics listener in `pkg/http/server/metrics/server.go` requires a supplied gatherer or handler and serves `/metrics`. Config.Address is a host, unlike Chi's complete Address string. Port zero selects an ephemeral listener. Enabled controls start; constructors still validate gatherer/handler and port. Fx lifecycle in `pkg/http/server/metrics/fx.go` loads `app.metrics`, adds a ten-second read-header timeout when zero, reports serving failures and requests shutdown. Plan `references/http/server/metrics/usage.md`.
- Chi's metrics listener uses `promhttp.Handler`, hence the default gatherer. `references/http/server/chi/metrics.md` must distinguish it from the independent listener. `recipes/metrics-listeners.md` must show actual collector/registerer/gatherer relationships. Installing modules does not unify registries.
- Tracing config in `pkg/otel/trace/config.go` and direct operations in `pkg/otel/trace/trace.go` delegate to the pinned go-otel dependency. Public configuration includes exporter type, sample-rate presence, batch/queue limits and duration timeouts. Fx Module in `pkg/otel/trace/fx.go` loads `app.open-telemetry`, distinguishes omitted from explicit zero sample rate, initializes on start and shuts down on stop. Span callers own End. Plan `references/otel/trace/usage.md`; verify delegated defaults against the selected dependency when authoring.
- GORM instrumentation in `pkg/otel/trace/gorm_fx.go` uses GORMModule instead of Module, checks `app.database.tracing.enabled`, requires an initialized GORM client, removes installed callbacks on stop, rejects duplicate instrumentation and suppresses query text/variables and plugin metrics. Plan `recipes/gorm-tracing.md`.
- Redis instrumentation in `pkg/otel/trace/redis_fx.go` requires RedisModule plus Module or GORMModule and `app.redis.tracing.enabled`. It accepts concrete `*redis.Client`, including go-redis failover clients, but rejects cluster and ring clients. Framework constructors also reject enabled cluster tracing. Hooks remain installed but become inactive on stop; weak-key state permits reuse. Statements, caller data and dial spans are disabled. Plan `recipes/redis-tracing.md`.

## Decorators and translation

Plan `references/i18n/service/usage.md` plus independently loadable `locale-loading.md`, `translation.md` and `error-translation.md` in that area.
